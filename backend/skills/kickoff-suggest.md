# kickoff-suggest Skill (Web API 적응 버전)

인터뷰 결과를 분석하여 사용자가 생각하지 못한 유용한 기능/구조를 최대 5개 제안하는 스킬.

---

## STEP 1 — 컨텍스트 분석 및 제안 생성

수집된 인사이트에서 아래 정보를 분석한다:

- 프로젝트 유형
- 기획 인터뷰 답변 (목적, 사용자, 핵심 기능, MVP 범위, 제약사항)
- 기술 스택, 데이터 소스, 리스크

### 제안 생성 규칙

1. **목적에 맞는 것** 우선 (쉬운 것, 유행하는 것 X)
2. **사용자가 이미 언급한 기능은 제안하지 않음** (중복 방지)
3. **제약사항에 위배되는 제안 금지** (예: Docker 불가인데 컨테이너 기반 제안)
4. **최대 5개** (scope creep 방지)
5. **각 제안에 반드시 포함**: 왜 유용한지 + 난이도 + 예상 시간

### 난이도 기준

| 난이도 | 의미 | 예상 시간 범위 |
|---|---|---|
| 낮 | 기존 구조에 자연스럽게 추가 가능 | 수 시간 ~ 1일 |
| 중 | 별도 모듈/연동 필요 | 1~3일 |
| 높 | 아키텍처 변경 또는 복잡한 외부 연동 필요 | 3일 이상 |

### 출력

message 필드에 마크다운 테이블로 제안을 작성한다:

```
## 💡 AI 추가 아이디어 제안

인터뷰 내용을 바탕으로, 프로젝트에 도움이 될 수 있는 아이디어를 제안합니다.
이 제안은 참고용이며, 채택하지 않아도 됩니다.

| # | 아이디어 | 왜 유용한가 | 난이도 | 예상 시간 |
|---|---|---|---|---|
| 1 | [제안 내용] | [1줄 근거] | 낮/중/높 | [시간] |
| 2 | [제안 내용] | [1줄 근거] | 낮/중/높 | [시간] |
| 3 | [제안 내용] | [1줄 근거] | 낮/중/높 | [시간] |
| 4 | [제안 내용] | [1줄 근거] | 낮/중/높 | [시간] |
| 5 | [제안 내용] | [1줄 근거] | 낮/중/높 | [시간] |

---

**어떻게 하시겠습니까?**
- 채택할 번호를 말씀해주세요 (예: "1, 3 채택")
- 수정해서 채택도 가능합니다 (예: "2번을 이렇게 바꿔서 채택")
- "전부 패스" — 제안 없이 다음 단계로 진행
```

insights 필드에는 제안 목록을 구조화하여 포함한다:
```json
[
  {"label": "제안 1", "value": "[제안 내용] (난이도: 낮, 시간: 2시간)"},
  {"label": "제안 2", "value": "[제안 내용] (난이도: 중, 시간: 2일)"}
]
```

step_complete는 false로 설정한다 (사용자 선택을 기다려야 함).

---

## STEP 2 — 사용자 선택 처리

사용자가 번호를 채택하면:

1. 채택된 아이디어를 MVP / MVP 이후로 분류한다
2. 분류 규칙:
   - 난이도 "낮" + 핵심 목적에 직결 → **MVP**
   - 난이도 "중/높" 또는 부가적 기능 → **MVP 이후 확장**
   - 사용자가 직접 분류를 지정하면 그것을 우선

### 채택 시 출력

message 필드:
```
## ✅ 채택된 아이디어

| # | 아이디어 | 분류 |
|---|---|---|
| 1 | [채택된 내용] | MVP |
| 3 | [채택된 내용] | MVP 이후 |

분류가 맞나요? 수정할 부분이 있으면 말씀해주세요.
없으면 다음 단계로 진행합니다.
```

insights 필드에 채택 결과를 포함:
```json
[
  {"label": "채택 제안 (MVP)", "value": "[제안 내용]"},
  {"label": "채택 제안 (이후 확장)", "value": "[제안 내용]"}
]
```

### 전부 패스 시 출력

message: "채택된 아이디어 없이 다음 단계로 진행합니다."
step_complete: true

---

## STEP 3 — 분류 확인 및 완료

사용자가 분류를 확인하면 (또는 수정 후 확인하면):

message 필드:
```
## ✅ 아이디어 제안 완료

**채택**: [N]개 (MVP: [n]개, 이후 확장: [m]개)

다음 단계에서 설계를 진행할지 선택하실 수 있습니다.
```

step_complete: true

---

## 주의사항

- 제안은 **강제가 아닌 참고용**임을 항상 명시
- "전부 패스"를 명시적 선택지로 항상 제공
- 이미 사용자가 기획한 기능과 중복되는 제안 금지
- 제약사항에 위배되는 제안 금지
- 난이도와 시간은 정확하지 않아도 됨 — 대략적 감만 제공
- 사용자가 5개 이상 추가 제안 요청 시 "킥오프 단계에서는 5개로 제한합니다" 안내
