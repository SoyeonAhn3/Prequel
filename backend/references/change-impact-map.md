# 섹션 변경 영향 맵 (Change Impact Map)

킥오프 문서의 섹션이 수정될 때, 이미 작성된 후속 섹션에 미치는 영향을 감지하고 알리는 경량 메커니즘.

---

## 1. YAML frontmatter — section_versions

각 스킬이 섹션을 작성/수정할 때 `section_versions`에 해당 섹션의 날짜를 기록한다.

```yaml
section_versions:
  1: "2026-05-18"
  2: "2026-05-18"
  7: "2026-05-19"
```

### 갱신 규칙

- 섹션을 최초 작성하거나 수정할 때 해당 키를 오늘 날짜(`YYYY-MM-DD`)로 갱신
- 여러 섹션을 수정하면 각각 갱신
- `section_versions` 키 자체가 없는 기존 문서에서는 최초 갱신 시 키를 추가

## 3. 변경 감지 규칙

스킬 실행 시 사전 조건 확인 후, 다음을 수행한다:

1. YAML frontmatter `section_versions`를 읽는다
2. 현재 스킬이 작성할 섹션 번호(N)와 의존 섹션 목록을 확인한다
3. 의존 섹션 중 `section_versions` 날짜가 **섹션 N의 날짜보다 새로운** 것이 있는지 확인한다
4. 새로운 것이 있으면 아래 알림을 출력한다

### 판정 규칙

- 현재 섹션이 `section_versions`에 없으면 (최초 작성): 감지 건너뜀
- 의존 섹션이 `section_versions`에 없으면: 해당 의존은 건너뜀
- 동일 날짜면: 같은 세션에서 작성된 것으로 간주, 건너뜀

---

## 4. 알림 형식

```
⚠️ 상위 섹션 변경 감지

이 스킬이 의존하는 섹션이 현재 섹션 작성 이후에 수정되었습니다.

| 변경된 섹션 | 수정일 | 현재 섹션 | 작성일 |
|---|---|---|---|
| 섹션 [N] | [날짜] | 섹션 [M] | [날짜] |

**어떻게 하시겠습니까?**
1. 변경 사항을 반영하여 현재 섹션 재생성
2. 현재 내용 유지 (수동 확인 후 진행)
```

### 사용자 선택 처리

| 선택 | 처리 |
|---|---|
| 1. 재생성 | 현재 스킬을 처음부터 다시 실행 (기존 섹션 덮어쓰기) |
| 2. 유지 | 알림을 기록만 하고 기존 내용으로 진행 |

---

## 5. 한계

- **동일 날짜 변경**: 같은 날 여러 스킬이 실행되면 날짜가 동일하여 변경을 감지하지 못할 수 있음. 이 경우 `kickoff-gap`의 교차 정합성 점검이 보완 역할을 한다.
- **수동 편집**: 사용자가 킥오프 문서를 직접 편집하고 `section_versions`를 갱신하지 않으면 감지 불가. 스킬을 통해 수정할 것을 권장.
